# ISO-5 inventory and supported tab shell

ISO-6b1 changes approved item purchase/sale Resource values, not inventory IDs/capacity/stack/selection/sort/discard APIs. Bag details use actual new unit sale prices. A full bag blocks the whole harvest before the owner's repeat phase changes; successful repeat harvest adds exactly the existing yield, with no additional seed consumption or ledger/wallet change until a real sale.

Owner approved commit ISO-4 and implement the ISO-5 plan. InventoryPanel retains its root path/public configure/toggle_inventory/close_inventory/slot_selected/inventory_toggled APIs. Main wires a small LifeInventoryController; no UI owns item quantities.

Scene pairs under ui/inventory: inventory_screen (VBox, tabs/header then wood/paper body), common_tabs (five native Buttons; only Bag 0 and Quest 2 enabled), filter_bar (all/seed/produce/tool/material), item_grid (ScrollContainer -> eight-column Grid, real indices and empty cells), inventory_slot (native Button with icon/quantity/selection), detail_card (actual item/name/category/description/count/sell_price; no invented stamina/quality/market modifier), capacity_footer (actual occupied/capacity, sort and contextual key hints), discard_prompt (inline confirmation with integer SpinBox, confirm/cancel). Root body has filter/grid/footer left and details/actions right; close/tabs remain outside scrolling content. Icon helper/controller and Theme builder remain separate small scripts.

InventoryPanel embeds screen/controller. Existing NpcJournal keeps its direct Main path and existing content/actions, adding the same common_tabs at active Quest index; dialogue stays unchanged. Main connects navigation through the inventory controller. Q/E cycle enabled Bag/Quest only; F selects current real stack through the existing slot_selected path, Z sorts only in the inventory. New InputMap actions: inventory_tab_prev=Q, inventory_tab_next=E, inventory_quick_select=F, inventory_sort=Z. World E/Q, existing B/I/Tab/J/Escape and day-end modal ownership remain intact. Unsupported tabs are disabled; eating/storage transfer are absent.

New domain APIs: InventoryState.revision (transient stale-action token), sort_slots() -> Array[int] (new-index -> old-index stable map), discard_from_slot(index: int, expected_id: StringName, expected_quantity: int, expected_revision: int, quantity: int) -> bool. Sort preserves all entries/quantities; discard validates exact current stack/version and emits normal item_removed notifications once. InventoryActions exposes stateless wrappers only. Selection remapping accounts for sorting/removed stacks; invalid/stale requests cannot affect another stack. No coin mutation is performed.

Config Resource data/inventory_config.tres supplies default_capacity=40, columns=8, visible_rows=5. ItemData adds category and optional description_key; current Resources add metadata only. Save v6 migration floors player capacity to config while preserving larger legitimate capacities and every valid slot/order/id/quantity, plus all v5 journal/day-end data. v1–v5 fixtures remain read-only.

Public view requests: common_tabs.tab_requested(index)/close_requested(), filter_bar.filter_requested(category), item_grid.slot_requested(index), detail_card.quick_selected()/discard_requested(), discard_prompt.confirmed(quantity)/cancelled(), footer.sort_requested(). Controller receives requests, validates live inventory/modal state and calls domain APIs. Grid filters retain original inventory indices. New roots use shared Theme variations without local StyleBoxes; scene children are constructed from their focused scripts. Three-size vi/en render/native-input checks compare with reference 06; reference PNGs never become assets.

LifeInventoryIcon creates cached AtlasTexture views of existing art, removing transparent margins without changing source art. InventoryPanel.attach_main(main) connects the journal header. HotbarPanel.selected_index()/active_tool() capture transient selection; remap_selection(order,previous_index,previous_tool) restores it after mutations without a second action. Controller queues grid refresh so emitting Buttons are not freed during signals. Wrapper scenes require no Inspector setup.
