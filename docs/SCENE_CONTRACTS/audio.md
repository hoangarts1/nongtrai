# Audio presentation contract — Phase7.2 (D103)

## Phase7.2c runtime loop composition (D105)

Main gains ambient_audio_flow:LifeAmbientAudioFlow and creates it after machine presentation is configured, under existing Main as AmbientAudioFlow (Node). No existing scene edits. Flow children are exactly MusicA/MusicB/AmbienceA/AmbienceB, all AudioStreamPlayer, two bounded crossfade slots per bus. No new autoload/input/state owner. configure(main:Node,source:AmbientAudioProfile=DEFAULT_PROFILE)->bool validates/deep-copies presentation data, binds one clock/weather listener and is idempotent for the same owner. get_playback_snapshot()->Dictionary returns detached enabled/zone/selected{music,ambience}/players[{id,instance_id,bus,playing,gain,target_gain,loop_mode}] for native diagnostics; it never becomes a save.

AmbientAudioContext is pure VIEW RefCounted. static select(profile:AmbientAudioProfile,cell:Vector2i,minute:int,rainy:bool)->Dictionary returns zone/ambience/music from validated data. First containing listening region wins, fallbackfarm; rain overrides night, night overrides regional daytime ambience. Music uses morning/afternoon bands and stops at night. Minute wraps like existing lighting. No actual WorldLocations/land/physics/ecology change.

Flow listens to GameClock.time_changed(day:int,minute:int) and Events.weather_changed(id:StringName), coalesces dirty context until its next process frame and checks only actual logical Player cell/game-start/title flags otherwise. Delta changes fade gain only, never world/time/state. Pause keeps ambience/music playing for audible settings preview. Title (even if Main._game_started remains true) immediately silences gameplay loops on reconciliation; Continue/load/NewGame reuse fixed slots, no layer accumulation. Rapid A→B→A reuses a matching slot or replaces the quieter slot; finished fades stop and release their old stream.

Loop playback clones native WAV Resource, sets LOOP_FORWARD/begin0/end=length*mix_rate, never mutates the shared import. Local gain is profile gain × fade; accepted settings are applied once via the7.2a Music/Ambience buses. Missing/invalid profile/stream fails silent with an internal warning, no fake playing state. Exit stops players; freed receiver signals disconnect natively. Existing SFX/preferences/draft/apply/rollback and save12 remain unchanged. Manual: F5 New/Continue, move to village/water/wooded listening regions, change day/night/rain, pause and Apply/cancel/mute/unmute, return title then Continue/load/NewGame. Native state/PCM checks do not claim human listening/finalOGG acceptance.

## Phase7.2b original loop assets/profile (D104)

AmbientAudioProfile (Resource) exports mix_rate:int, fade_seconds:float, day_start/afternoon_start/night_start:int, tracks:Array[Dictionary], zones:Array[Dictionary], day_by_zone:Dictionary, night_track/rain_track/morning_music/afternoon_music:StringName. Track fields id:StringName, path:String, bus:StringName, gain:float, seconds:float. Zone fields zone:StringName, region:Rect2i; order wins on overlap, default isfarm. These are cosmetic listening regions, not terrain/ownership/ecology. API validation_errors()->PackedStringArray checks numeric/type/ID/reference/route/range invariants; get_track(id:StringName)->Dictionary returns a detached row. Actual file/PCM checks live in the additive asset test, not a new registry owner.

Eight original mono16bit/22050Hz WAVs are offline placeholders, replaceable at their data-owned paths: amb_farm_day, amb_forest_day, amb_village_day, amb_water_day, amb_night, amb_rain, mus_farm_morning, mus_farm_afternoon. Ambient loops12s, music16s; authored synthesis is not a field recording/final soundtrack. WAV instead of targetOGG is explicitly approved; no codec installation/download. Native imported WAVs use uncompressed PCM and keep loop disabled; runtime7.2c must clone streams before changing loop properties. No shared imported Resource mutation.

Builder: pinned Godot --headless --path . --script res://tools/build_ambient_audio.gd -- --output=res://assets/audio . --output is required, only these eight track IDs are written, errors exit1; probe output must be outside project assets. It reads profile, generates deterministic bytes and checks write/flush errors. No four existing tool WAVs or their import settings are changed. No Node/Inspector/runtime playback is added in7.2b.

## Phase7.2a bus routing

No existing scene, node path, autoload, InputMap or save change. Godot loads default_bus_layout.tres: exactly Master, Music, SFX, Ambience, UI; all children send directly to Master. Initial gains are unity; no bus effects. LifeAudioBusRouter is transient core RefCounted, not a scene/autoload/state owner. API: is_layout_ready()->bool (static), apply_accepted()->bool. It validates every required bus/send before modifying gains, reads accepted Settings and sets Music=music_volume, Ambience/UI=effects_volume, SFX=1. Master is not changed. Invalid layout returnsfalse without partial mutation; the router never silently rebuilds another layout.

Existing AudioService remains the same Main-owned Node and public play_sound/get_sound_path API. It owns one RefCounted router, no extra child nodes. _ready applies accepted bus gains then connects its existing single preferences_changed listener. Accepted changes update bus gains and active SFX players; new SFX players use busSFX plus their original effects_volume volume_linear. SFX bus unity avoids double attenuation. If required layout is missing, existing playback falls back toMaster and warns on setup; no file/owner repair. Missing clip behavior and finished-player cleanup remain.

Phase7.2b will add standalone assets/profile; Phase7.2c will add runtime loop selection only after their own gates. No loop or music is enabled in7.2a. Native API/geometry here means pinned engine reflection and actual bus/player properties, not a human listening certificate. Test fixtures snapshot/restore bus layout and isolated Settings bytes; no editor wiring or manual bus creation is required.
